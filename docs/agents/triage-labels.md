# 分诊标签

各技能使用五个规范的分诊角色。本文件把这些角色映射到本仓库 Issue 跟踪器中实际使用的标签字符串。

| mattpocock/skills 中的标签 | 本仓库跟踪器中的标签 | 含义                               |
| -------------------------- | -------------------- | ---------------------------------- |
| `needs-triage`             | `needs-triage`       | 需要维护者评估                     |
| `needs-info`               | `needs-info`         | 等待报告者补充信息                 |
| `ready-for-agent`          | `ready-for-agent`    | 已完整说明，可交给无人值守的智能体 |
| `ready-for-human`          | `ready-for-human`    | 需要人工实现                       |
| `wontfix`                  | `wontfix`            | 不予处理                           |

当技能提到某个角色（例如“打上可交给智能体的分诊标签”）时，使用上表中对应的标签字符串。

如需改用其他命名，直接修改“本仓库跟踪器中的标签”一列即可。

## 非分诊专用标签

以下标签用于特定自动化工作流，**不进入上述五角色分诊流程**，也不使用分诊脚本自动派单或关闭：

| 标签字符串 | 维护方 | 用途与处理约定 |
| --- | --- | --- |
| `deps-breaking` | `.github/workflows/deps.yml` 与 `tool/deps_report.dart` | 标记仓库中唯一一个“第三方依赖破坏性更新”跟踪 Issue（固定标题 `第三方依赖有可做的破坏性更新`）。由智能体评估破坏性升级影响并给出建议后，由维护者决定何时升级，详见 `docs/engineering/dependencies.md`。 |
